# v0.23.0 performance verification

The comparison base is `f1494125a032d973b26503a73895d79a9aa9626f`, the pre-optimization main branch. Gameplay ranges, damage, population limits, terrain checks and line-of-sight rules are retained. Navigation retry cadence now also applies to unsuccessful/exhausted routes. Explicit skirmish orders stagger the first search by 0–150 ms while local steering starts immediately.

## Frozen navigation workload

`tools/endgame_path_bench.rs` runs 32 fixed searches on a 160×160 arena, one warmup and five timed batches per scene. Scenes are open terrain (8400 expanded-node budget), two detour walls (30000), and an unreachable sealed goal (8400). Both versions use the same heap ordering, endpoints, collision callbacks and budgets. Every route checksum matched.

Measured on Windows with rustc 1.96, `-O`, while the two-job game build ran in the background. These CPU timings are approximate and do not measure rendered FPS.

| Scene | Baseline median per 32 searches | Reusable workspace median | Ratio |
| --- | ---: | ---: | ---: |
| Open | 170.712 ms | 50.259 ms | 3.40× |
| Detour | 474.024 ms | 119.820 ms | 3.96× |
| Unreachable | 202.980 ms | 75.324 ms | 2.69× |

PowerShell reproduction from the repo root:

```powershell
New-Item -ItemType Directory -Force target | Out-Null
git show f149412:crates/core/src/pathfinding.rs | Set-Content -Encoding utf8 target/legacy_pathfinding.rs
rustc --edition 2024 -O --cfg legacy tools/endgame_path_bench.rs -o target/path-legacy.exe
./target/path-legacy.exe
```

Regression coverage includes route budgets, cliffs, bridge crossings, thin walls/gates, live blocker changes using the same workspace, map resize, generation-counter wraparound, and a failed-route schedule at 60 fps. That schedule performs 3 searches in 120 frames rather than retrying every frame.

## Target selection and army assets

`tools/endgame_target_bench.rs` checks every selected target against a contiguous brute-force selector at 32/128/512/1024 targets, in dispersed and compact formations. Units retain priority over buildings and original snapshot rank breaks distance ties. The benchmark includes index rebuild cost. The 512/1024 cases are synthetic stress beyond the game's normal 80-per-side population ceiling, not a claim about typical army sizes.

Spatial links alone regressed compact armies; the final implementation falls back to contiguous scans for small/compact sets or queries containing most targets. The 1024-target dispersed workload measured 129.955→41.144 ms per 32 frames. The compact workload measured 217.666→222.637 ms (approximately 2% overhead), so no improvement is claimed for that case. Short noisy samples at low counts are not a speedup claim.

```powershell
rustc --edition 2024 -O tools/endgame_target_bench.rs -o target/target-bench.exe
./target/target-bench.exe
```

Independent Bevy regression tests verify that repeated outfits share complete mesh sets and neutral materials while retaining separate rigs; different roles/colours/child/desert styles remain distinct; active hurt-flash and viewmodel materials cannot become neutral troop skins. The world-owned LRU holds at most 256 outfits, populated lazily; ordinary skirmish variants fit within this bound. Crowd separation retains the original pair and summation order using flat links instead of per-cell heap allocations.

## Full-game scenarios

Use separate test data directories (`APPDATA`) to keep real save slots/settings untouched. Set `BEVY_ASSET_ROOT` to this checkout. Sampling starts 15 seconds after the world and requested armies are ready, requires at least 20 seconds total, and reports mean/p50/p95/p99/max frame times only while gameplay is active. Runs with no post-warmup gameplay samples fail. `FOREST_PERFFREEZE` reports `mode=render_frozen` separately.

```powershell
# Late campaign night; sustained churn, developed town and archers.
Get-ChildItem Env:FOREST_* | Remove-Item
$env:BEVY_ASSET_ROOT=$PWD.Path; $env:RUST_LOG='info'
$env:APPDATA=Join-Path $PWD 'target/perf-campaign-data'
New-Item -ItemType Directory -Force $env:APPDATA | Out-Null
$env:FOREST_RES='1280x720'; $env:FOREST_QUALITY='high'
$env:FOREST_CAM='0,15,30,0,2,-8'
$env:FOREST_PERFTEST='300'; $env:FOREST_WAVE='7'
$env:FOREST_PERF_COUNT='96'; $env:FOREST_DEFEND='1'
$env:FOREST_IMMORTAL='1'
$env:FOREST_TOWN='full'; $env:FOREST_ARCHERS='64'
./target/release/tileworld_bevy_forest.exe

# Full skirmish armies: clear campaign staging variables first.
Get-ChildItem Env:FOREST_* | Remove-Item
$env:APPDATA=Join-Path $PWD 'target/perf-army-data'
New-Item -ItemType Directory -Force $env:APPDATA | Out-Null
$env:FOREST_RES='1280x720'; $env:FOREST_QUALITY='high'
$env:FOREST_PERFTEST='120'; $env:FOREST_RTS_CAM='0,0,60'
$env:FOREST_RTS='1'; $env:FOREST_PERF_ARMY='72'
./target/release/tileworld_bevy_forest.exe
```

`FOREST_PERF_ARMY` uses the same soldier spawn, movement, targeting, combat and death systems as real training. Each side remains below the real hard population limit; logs must confirm the actual spawned count. The campaign fixture repairs the keep after damage and makes the spectator hero immortal; the army fixture gives its Town Halls extra HP. These fixture-only protections prevent defeat from freezing the workload; native soldier stats and ordinary game rules are unchanged. A run ending outside `Playing` / `Modal::None` fails, except deliberate `render_frozen` runs. Require no missing assets, no panic/validation error, and a valid `PERF_SUMMARY`; track entity/mesh/creature-material/image/font-atlas counts throughout.

Older releases ignore numeric `FOREST_WAVE` and `FOREST_PERF_COUNT`, so an old night-1/36-invader run cannot establish a rendered-FPS improvement for this night-7/96-invader scenario. Full-game results below are absolute smoke/stability measurements; the before/after claims above are limited to their frozen CPU workloads.

## Windows release validation (2026-10-06)

`cargo test --workspace --release --locked -j2` passed all 444 tests: 128 game tests, 311 core unit tests, 1 reachability integration test and 4 serialization tests. The final executable reports version 0.23.0. The normal RTS economy smoke passed after 90 seconds: wood +52, food +21, two trained swordsmen.

Final first-person and mixed-outfit in-engine captures saved successfully, exited with code 0 and were visually inspected. Both had zero missing-asset errors or panics. A case-sensitive catalogue check also confirmed every recorded voice file exists; the two unrecorded rival reactions are excluded from playback and preloading.

Hardware: i5-12400F, 32 GiB RAM, RTX 5060 Ti 16 GiB, Vulkan driver 616.64. Full-game runs use 1280×720/high, default vsync and an unfocused window on a shared Windows desktop. These are bounded smoke runs, not a 50-minute degradation or multi-hour leak proof.

The 300-second campaign run reached readiness at 11.336 s and remained `Playing` / `None` throughout. Meshes settled at 5152–5164 after the initial deaths; creature materials stayed at 8. RSS rose from 3.69 GiB at 32 s to 4.29 GiB, then stayed at that level through the last minute. The 120-second RTS run confirmed 72 soldiers spawned for each side, readiness at 28.070 s, and retained active gameplay throughout. Soldiers die normally, so this is a large-battle/attrition smoke, not a sustained 144-living-soldier benchmark. From 45 s onward it held 1612 meshes, 3 creature materials and 14 font-atlas pages; RSS was 1.89–2.14 GiB.

Both initial runs used BelowNormal process priority. Their full summaries retain substantial stalls rather than filtering them away:

| Workload | Sampled frames | Mean ms | p50 ms | p95 ms | p99 ms | Max ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Campaign, BelowNormal | 14070 | 21.361 | 16.643 | 19.682 | 24.301 | 30734.033 |
| RTS attrition, BelowNormal | 2607 | 29.515 | 16.594 | 21.034 | 29.988 | 21714.535 |

Other Python workloads were active on this desktop. That does not establish the cause of these stalls. A 300-second campaign repeat changed only process priority to Normal and enabled `FOREST_SPIKEWATCH=1`. Readiness was 10.967 s; all periodic state checks remained `Playing` / `None`, with no missing assets or errors. It sampled 16420 frames: mean 16.691 ms, p50 16.619 ms, p95 19.422 ms, p99 21.545 ms, max 59.053 ms. Sampled elapsed time covers the full post-readiness/warmup interval. Creature materials stayed at 8; font atlases settled at 22 pages; RSS reached 4.32 GiB and held through the final minute. The multi-second stalls did not reproduce in this run, but this is not proof of their cause or elimination. The earlier results remain part of the evidence; no across-release FPS gain is claimed.
