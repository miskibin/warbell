# Warbell campaign environment asset contract

This is a separate Blender MCP authoring lane. `assets/models/blender_trees/`, `art/blender_trees/`, and `tools/blender_trees/` are frozen and untouched.

Each static environment model is exported as `<name>.json` under `assets/models/blender_environment/`. A **single** `environment_kit.glb` holds all named meshes and embeds the two shared material lanes only once; it does not create a duplicate GLB per object. JSON schema `warbell.blender_environment_mesh.v1` contains `name`, `atlas`, `material`, `positions`, `normals`, `uvs`, `colors`, `indices`, `bounds`, and `triangles`. Coordinates are Bevy Y-up, world-unit scale, root/base at Y=0, front toward +Z for architecture. RGB vertex colours are linear multipliers; UVs use PNG top-left origin. All JSON attributes and indices are decoded from each corresponding **named GLB node/mesh** and independently validated by `validate_kit.py`. One indexed mesh and one material per object or variant. The runtime owns placement, collision, interaction, visibility and progression.

Material lanes: `surface_atlas.png` for opaque stone, plaster, wood, shingles, thatch, earth, iron, bronze, cloth, straw and rock; `vegetation_atlas.png` for alpha-mask grass, leaves, crops and ground plants. Every mesh states `atlas` and `material` (`opaque` or `cutout`). Opaque JSONs also state `orm_atlas: "surface_orm.png"` and `emissive_atlas: "surface_emissive.png"` on the same UVs. ORM is linear (Non-Color) and follows glTF convention: R=AO, G=roughness, B=metallic. Emissive is almost black because live lighting remains in code. Terrain textures are separate tileable images, since subregions of a shared atlas cannot repeat over the island without crossing into neighbouring patches.

The interchange GLB cutout material uses glTF `MASK` default alpha cutoff 0.5; the Bevy runtime uses cutoff 0.35 and coverage-preserving mip generation for thin foliage. `texture_spec.json` records the interchange cutoff.

Existing castle transforms stay in effect. Keep local 7×6 with root scale `(0.88, 0.805, 0.88)`; wall lengths 15 and 10 local units with Y scale 0.78; gate has 4-unit opening and Y scale 0.8; corner tower root scale `(0.92, 0.851, 0.92)`; four house styles use root scale `(1.215, 1.14975, 1.215)`. House local footprints: hut 2×1.7, cottage 2.6×2, townhouse 2.3×1.9, longhouse 3.6×1.8. Twelve castle house slots use those four styles. Town producer plots are about 4×3 with main building on the −X half and walkable yard on +X. Keep tiers remain separate additive assets so upgrades reveal them without changing gameplay. Static frames can replace visuals around animated doors/bells, banners, flames, shutters and window lights; those animated children keep their logic.

Ground images are `ground_{grass,forest,rocky,swamp,desert,snow,path,cobble}_{albedo,normal,roughness}.png`, tileable 512². Albedo is sRGB, normal is tangent-space OpenGL (+Y), roughness is grayscale. One repeat tile is designed for roughly 2–3 world units. Island terrain height, collision and road field remain parametric gameplay data.

Meadow grass and path albedo import the task-specific imagegen PNGs in `art/blender_environment/imagegen/`. Forest ground imports the CC0 Poly Haven `leafy_grass` diffuse, OpenGL normal and roughness triplet; `stony_dirt_path` is retained as a separate dark alternate triplet while the main campaign path remains lighter. The other ground families and two material atlases remain procedurally authored. Imported diffuse maps are not colorized by the Blender baker. `texture_spec.json` and the manifest retain source hashes, and all final 512² maps are baked through Blender MCP.

All authoring and export must execute inside isolated Blender through official `mcp-for-blender` `execute_blender_code` on port 9877; keep `mcp_calls.jsonl`. Deliver editable `.blend` source, manifest with source/license/hashes/triangle/bounds, GLB validator report, Blender studio preview and in-game QA views. Do not author RTS buildings or character/animal/hero assets.
