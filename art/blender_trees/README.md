# Warbell Blender tree study assets

Five trees were authored in Blender 4.5.9 through the official `mcp-for-blender` `execute_blender_code` bridge. The editable source is `warbell_trees.blend`; `studio_preview.png` is a neutral CPU Cycles render. The game consumes the five Y-up JSON meshes in `assets/models/blender_trees/` plus the single 1024×1024 RGBA atlas. The GLBs provide standard exchange files and an independent reference for the JSON attributes.

| Model | Triangles | Height (world units) |
|---|---:|---:|
| oak_a | 1,394 | 1.886 |
| oak_b | 1,394 | 1.913 |
| birch_a | 1,170 | 1.759 |
| birch_b | 1,170 | 1.731 |
| pine_a | 1,668 | 2.422 |

Each JSON has one indexed mesh with `positions`, `normals`, `uvs`, `colors`, and `indices`; its lowest Y is exactly 0. Normals and linear vertex color multipliers are decoded from the exported GLB to ensure the game uses the same shading data as the Blender reference. The atlas uses alpha-cutout foliage and fully opaque bark, allowing one material and one entity per tree. UVs use the PNG's top-left origin. Oak, birch, and pine foliage occupy the top-left, top-right, and bottom-left quadrants; bark occupies the bottom-right quadrant. The GLBs declare `alphaMode: MASK` and include the atlas.

The leaf silhouettes reuse the `oakL.png`, `aspenL.png`, and `pineL.png` cutouts already shipped in `assets/textures/leaves/` from **dgreenheck/ez-tree (MIT)**; they are recolored to a summer palette. Bark artwork and branching structures are newly generated by `tools/blender_trees/make_atlas.py` and `build_trees.py`. `tools/blender_trees/mcp_calls.jsonl` records the actual MCP executions. `manifest.json` includes the SHA-256 of each delivered core artifact.

The build sequence is `python tools/blender_trees/make_atlas.py`, start the isolated Blender bridge with `tools/blender_trees/start_mcp.py` on port 9877, then run `python tools/blender_trees/mcp_client.py tools/blender_trees/build_trees.py`. Run the same client on `render_preview.py` for the studio frame. The five GLBs passed the Khronos validator with zero errors and warnings; results are in `gltf_validation.json`.

Authoring requires Blender 4.5.9, the `mcp-for-blender` 2.1.9 add-on/server, and a Python environment with MCP, Pillow and NumPy. Set `BLENDER_MCP_ADDON_DIR` to the folder containing `blender_mcp_addon.py`. If that add-on needs external Python dependencies, set `BLENDER_MCP_SITE_PACKAGES` to their site-packages folder; the bridge appends it after Blender's native packages to preserve NumPy ABI compatibility. The client locates `mcp-for-blender` beside its Python interpreter or on PATH, or accepts `BLENDER_MCP_COMMAND`. Set `BLENDER_MCP_DISABLE_TELEMETRY=1` before starting Blender. Use an isolated process and verify port 9877 is free.

For GLB validation, install the pinned package with `npm install --prefix tools/blender_trees` and run `node tools/blender_trees/validate_glb.cjs`. An existing installation can be selected with `GLTF_VALIDATOR_MODULE`. Authoring helpers do not run inside the game and add no runtime dependency.
